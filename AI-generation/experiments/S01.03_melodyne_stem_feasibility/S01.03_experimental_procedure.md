## 2. Section Selection Criteria

The 16-measure Melodyne target is identified as an output of the structural fidelity pass (§4.1). The selected passage must satisfy all of the following.

1. Length: 16 target measures with 2-measure handles on both sides.
2. Content: the stem set for the candidate zone must contain identifiable melody, clear bass function, and moderate harmonic density across the available stems.
3. Form: at least one phrase boundary and one cadence within the target window.
4. Texture: no exceptionally dense tutti material across the full stem sum.
5. Metric stability: the candidate zone must show acceptable conformance to the DP grid after §4.1 alignment — no unresolved splits or elisions within the target window.

Having 9 individual stems available (rather than only the stereo mix) is expected to improve Melodyne's note extraction accuracy by reducing polyphonic ambiguity per track. Whether this expectation holds is one of the evaluation questions for this pilot.

Record section metadata (§2.1) at the end of §4.1, before proceeding to §4.2.

## 3. Fixed Conditions

The following are locked for this pilot and may not be varied without a decision log entry.

1. One selected Suno version only. Selection is a curatorial act performed across multiple Suno generation iterations and is governed by one of two criteria:
   - **Fidelity criterion:** the output most closely adheres to the structural, metrical, and motivic framework of the DP transformation.
   - **Discovery criterion:** the output contains something compositionally valuable that emerged from Suno independent of the original transformation.
   Both criteria are valid; the governing criterion for the selected version must be recorded in §2.1 (Selection rationale).
2. Melodyne as the sole transcription engine.
3. Comparison scope:
   - Full DP-positioned mix render
   - Melody stem
   - Bass stem
   - Harmonic/accompaniment stem
4. No aggressive preprocessing beyond level matching and documented trimming.

## 4. Procedure

### 4.1 Structural Fidelity Pass and Section Selection

This phase operates on the full-length Suno result. It aligns the Suno output to the DP MIDI structure, characterizes metrical and hierarchical drift, and identifies the best 16-measure candidate for the Melodyne pilot. This alignment is a permanent step in the iterative workflow — required on every loop cycle to maintain synchrony with the pre-Suno transformation material.

Temporal authority is always Suno: the DP tempo map/conductor track is adjusted to follow the Suno audio's native timing. The Suno audio is never time-stretched to fit the DP grid. The two variants below differ only in how divergent content is handled, not in timing authority.

1. Select target section and handles per §2.
2. Place selected Suno result into DP against the source structure. Export a conductor map at this point (pre-conform baseline).
3. Produce two alignment variants in parallel:

   **Variant A — Cut/elide at divergence:** Where Suno's content diverges from the DP transformation structure, split or elide the Suno track. Preserve the original unedited Suno audio on a separate track. Export a conductor map after adjustment.

   **Variant B — Retain at divergence:** Allow the Suno content to continue through divergent zones without cuts; accept the structural difference. Export a conductor map after adjustment.

4. Compare the two variants. Select the best-performing zones from either for the working version. Document which zones were taken from which variant and why.
5. Bounce a DP-positioned transcription render from the selected working version.
6. Version 2 reintegration (optional): identify any Suno sections with compositional value outside the original transformation and reintegrate where desired. Document which sections were reintegrated.
7. Select the 16-measure Melodyne target from the working version, satisfying all criteria in §2. Complete §2.1 Section Metadata before proceeding.

> **Gate:** Do not proceed to §4.2 until §2.1 is complete and the 16-measure target is confirmed.

### 4.2 Stem Intake and Reconstruction Check

#### 4.2.0 Prepare the 16-Measure Extract Artifacts

Complete this before any stem import. All Melodyne work operates on this extract, not the full-length Suno result.

1. **Create a new DP chunk** sized to cover: 1 measure of silence + any pickup beats preceding the target start + 16 target measures + 2-measure handle at the end. Name the chunk using the standard convention, e.g. `08-mm[S-start]-[S-end]-V[n]-16mExtract`.
2. **Copy MIDI material** from the working-version chunk (produced in §4.1) into the new chunk for the relevant measure range. Preserve all tempo and meter information. Under Variant B, this MIDI is a reference layer — it will not lock perfectly to the Suno audio. The divergence is not fabrication: Suno draws from the same source material but may compress or expand metric measure counts and occasionally reorder chords. Expect some drift between the DP MIDI reference and the Suno audio; this is observable evidence, not an error.
3. **Export the conductor track** from the new chunk as SMF. This is the tempo map file for Melodyne.
4. **Trim and prepend each stem.** For each of the 9 Suno stem files:
   - Trim the audio to the time range corresponding to the new chunk (16 measures + handles), starting from the S1 downbeat of the new chunk.
   - Prepend silence equal to the duration of the 1-measure lead-in (S1 of the new chunk). This places the Suno pickup correctly within the beat grid — the pickup audio lands after the silence but before S2, exactly as it does in the main project.
   - Name each output file using the soundbite convention: `08-finale-mm39-55-[stem-label]-16m.wav` (e.g. `08-finale-mm39-55-Lead-Vocal-16m.wav`). Use hyphens within stem labels to avoid shell quoting issues. The full mix file (`0 PaTo Argument I.ii.b.wav`) does not need to be rebounced; the original on disk serves as the reference if needed.
5. **Verify alignment**: import one stem and the SMF into Melodyne as a quick check that the waveform's first transient sits at the expected beat position before importing all stems.

, not an instrument-isolated separation. Stem labels reflect Suno's model-defined categories and may not correspond to the acoustic instruments in the original. A stem labelled "Viola" may carry residual transients from other string chords; a stem labelled "String Section" may contain bleed from multiple sources. Evaluate each stem by ear as well as by label. Unexpected sonic content is not an error to discard — it is a Suno-generated transformation and may have independent compositional value.

1. Import all available Suno stems at common origin (do not align by first transient).

### 4.3 Melodyne Passes

#### 4.3.0 Melodyne Studio — Step-by-Step Import (Standalone, first use)

**One-time setup**
1. Launch Melodyne Studio. A blank document opens.
2. Import the SMF tempo map: open the **Tempo Editor** and switch to **Assign Tempo Mode** if necessary, then go to **File > Import Tempo...** and select the conductor track SMF. Alternatively, drag the SMF directly onto the Tempo Editor window. Melodyne reads tempo and meter events from the file; note events are ignored.
3. Confirm the grid is correct: the bar ruler at the top of the document should reflect the tempo and any meter changes from the DP session.

**Load stems**
4. Drag the first stem WAV file into the Melodyne document. A new track is created and Melodyne analyses the audio automatically. Wait for analysis to complete (progress indicator) before loading the next file.
5. Drag each remaining stem in one at a time. Keep the numbered order (1 Lead Vocal, 2 String Section, etc.) to match the stem table.
6. Verify that the waveform heads of all tracks align: the 1-measure silence at the top should be visible on every track before the audio content begins.

**Set algorithms (per track)**
7. Right-click the track name → **Set Algorithm** → choose from the table in §4.3.1. Do this for every track before playing anything — Melodyne re-analyses when the algorithm changes.
8. For R02 (2-stem probe): try the default algorithm first, then re-run with an alternative algorithm on the same stem to compare results. Log each variant as a sub-pass (e.g. R02a, R02b).

**Review and export**
9. Play through each track and visually inspect the blob detection. Look for: octave errors, spurious blobs in silent passages, absent notes in obvious melodic lines. Do not correct anything yet.
10. Export raw MIDI before any editing: **File > Export MIDI** → select **A common file for all tracks** → name the file `08-finale-mm39-55-[stems]-raw-R02.mid`.
11. **Quit Melodyne before opening DP.** Running both standalone simultaneously causes Core Audio driver conflicts that crash DP. Always launch DP with the audio output device matching the one saved in the project (built-in speakers by default). To switch output devices while DP is running, use DP's own hardware configuration window — do not use the macOS system audio controls or menu bar volume switcher while DP is open, as this crashes DP regardless of project state.
12. Log the result in `S01.03_run_log.csv`.

Algorithm assignment is based on what each stem sounds like, not its label. Listen to each stem before assigning. The table below gives defaults based on label; override if the audible content differs.
