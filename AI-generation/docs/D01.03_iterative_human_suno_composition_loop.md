# D01.03 Iterative Human–Formal–Suno Composition Loop

Document Status: Draft v0.1

Source: Promoted from `suno_to_midi_multi_stem_extraction_workflow.md`

## 1. Purpose

This document defines an end-to-end iterative workflow for generating new music by cycling between:

- legacy source material ("dead composer")
- formal rule extraction and transformation
- Suno audio-conditioned generation
- stem-based symbolic reconstruction (MIDI primitives)
- DAW-based manual alignment/editing
- additional human or formal manipulations

The workflow is designed to be modular and repeatable. It avoids reliance on high-level musical semantics (e.g., function/scale-degree naming) and instead treats music as a time-stamped event structure (pitch, onset, duration, velocity) plus transformation rules.

---

## System Overview (Macro Loop)

### Loop States

1. **Legacy Source Piece (L0)**
2. **Formal Rule/Transform Extraction (F1)**
3. **Transformed Score/Structure Generation (G1)**
4. **Suno Audio-Conditioned Generation (S1)**
5. **Selection + Curation (C1)**
6. **Suno Output → Stems → MIDI Primitives (E1)**
7. **DAW Alignment and Manual Correction (A1)**
8. **Next-Round Human/Formal Manipulation (G2)**
9. **Feed Forward to Suno Again (S2)**

This repeats as an iterative design spiral:

L0 → F1 → G1 → S1 → C1 → E1 → A1 → G2 → S2 → …

---

## Stage 0 — Legacy Source Acquisition (L0)

### Inputs

- Audio recordings and/or symbolic editions (scores, MIDI, MusicXML if available)
- Reference performances (multiple interpretations if available)

### Output

- Canonical “source work bundle” for analysis (audio + metadata + any symbolic forms)

---

## Stage 1 — Formal Transformation Rule Extraction (F1)

### Goal

Derive a formal set of transformation rules that capture the structural behavior of the source work.

### Examples of Rule Families (non-semantic, structural)

- Event-level pitch transforms (transpose, invert, map-to-set)
- Rhythm transforms (augmentation, diminution, stochastic timing noise)
- Phrase transforms (reorder segments, splice, interpolate)
- Statistical trajectory transforms (vector field constraints, distribution fitting)
- Orchestration role transforms (register mapping, density constraints)

### Deliverable

- A machine-readable transformation specification (e.g., JSON/YAML ruleset)
- Optional: a set of transformation operators as code modules

---

## Stage 2 — Generate a New Structural Piece (G1)

### Inputs

- Source work bundle
- Transformation specification

### Output

- A new symbolic/structural representation (event list, MIDI, or equivalent)
- Optional: a rendered audio draft for Suno conditioning

---

## Stage 3 — Suno Generation with Prompt + Audio Conditioning (S1)

### Inputs

- Prompt text (style guidance, instrumentation targets, constraints)
- Audio input (rendered from G1)

### Output

- Multiple candidate Suno outputs (audio)

---

## Stage 4 — Curation / Selection (C1)

### Goal

Select a candidate Suno output to serve as the basis for symbolic reconstruction and further iteration.

### Outputs

- Selected Suno master audio
- Associated Suno stems (as provided)

---

## Stage 5 — Suno Output → Stems → MIDI Primitive Extraction (E1)

This stage reconstructs primitive note events from Suno stems using Melodyne + post-processing.

### Inputs

- Suno stems (token-like decomposition)
- Optional: aggregate mix as validator

### Outputs

- Per-stem MIDI tracks with primitive note events:
  - integer pitch
  - onset time
  - duration
  - velocity

### Sub-Workflow (Detailed)

#### 5.1 Input Preparation

- Verify stems are sample-aligned, same sample rate, start time = 0.
- Import into DAW (Digital Performer): one audio track per stem.
- Optional: import the master mix as an additional validator track.

#### 5.2 Melodyne Extraction (Per Track)

- Insert Melodyne via ARA on each audio stem.
- Choose algorithm per stem:
  - Vocals: Melodic
  - Bass: Melodic
  - Drums: Percussive (optional)
  - Other: Universal / Polyphonic (cautious)
  - Mix validator: Melodic or Universal
- Drag extracted notes to corresponding DAW MIDI tracks (one MIDI track per stem).

#### 5.3 MIDI Track Configuration

Suggested channel mapping (optional but consistent):

- Ch 1: Lead/Vocal
- Ch 2: Bass
- Ch 3: Other (Topline)
- Ch 4: Other (Comp/Harmony, if retained)
- Ch 10: Drums

#### 5.4 Post-Processing (Per Track)

Primitive-only cleanup rules:

- Minimum duration thresholds (lead/bass/other tuned separately)
- Merge adjacent same-pitch notes with small gaps
- Remove micro-notes (short + low velocity)
- Stabilize pitch jitter (collapse rapid oscillations)
- Velocity normalization/compression

#### 5.5 Cross-Track Arbitration (Optional but recommended)

- Treat stems as higher-confidence than mix.
- Use mix track to fill gaps or validate candidate events.
- Suppress duplicates across tracks.

#### 5.6 Exports

- Keep per-track MIDI in the DAW for editing.
- Optional export artifact: Type-1 multi-track MIDI.
- Optional internal artifact: JSON event list with track IDs.

---

## Stage 6 — DAW Alignment and Manual Correction (A1)

### Goal

Align the extracted MIDI primitives to the selected Suno performance so the symbolic representation matches the audio realization.

### Inputs

- Selected Suno master audio
- Extracted per-stem MIDI tracks

### Core Activities

- Time alignment adjustments (rubato matching)
- Note boundary edits (trim, extend, merge)
- Pitch corrections (octave errors, mis-snaps)
- Velocity shaping (match phrasing/energy)
- Track pruning (remove artifacts)

### Outputs

- A “performance-mapped” MIDI/structure that corresponds to the Suno audio

---

## Stage 7 — Next-Round Human or Formal Manipulation (G2)

### Goal

Generate a new structural piece derived from the Suno-realized performance, using either:

- human compositional edits, and/or
- another pass of formal transformations

### Inputs

- Performance-mapped MIDI/event structure

### Outputs

- New symbolic structure (G2) ready to be rendered as audio for Suno conditioning

---

## Stage 8 — Feed Forward to Suno Again (S2)

### Inputs

- Prompt (revised or consistent)
- Audio render of G2

### Outputs

- New batch of Suno candidates

This completes one loop cycle.

---

## Repeat Loop

Each iteration yields:

- a new curated Suno performance
- a reconstructed symbolic primitive representation
- a refined transformation ruleset (optionally)

The process is intentionally evolutionary:

- rules can be updated based on what “survives” the Suno rendering
- extraction constraints can be tuned based on observed failure modes

---

## Practical Notes / Known Constraints

- Suno stems are not guaranteed to be instrument-isolated; treat them as model-defined decompositions.
- Polyphonic reconstruction from dense stems is the dominant failure mode; prioritize role tracks (lead/bass/topline) over exhaustive chord recovery.
- Rubato requires seconds-first editing; any tick/grid mapping should be optional and derived.

---

## Suggested Artifacts for Each Iteration

Per iteration (n):

- Suno master audio (Sn)
- Suno stems bundle (Sn-stems)
- Extracted MIDI bundle (Sn-midi-raw)
- Cleaned/arbitrated MIDI bundle (Sn-midi-clean)
- Performance-mapped MIDI bundle (Sn-midi-mapped)
- Next symbolic generation source (Gn+1)
- Updated ruleset (Fn+1) if rules evolve

---

## Summary

This workflow integrates:

- formal transformation research
- AI-audio generation
- symbolic reconstruction
- DAW-based performance mapping

into a repeatable loop for iterative composition. It treats music as a primitive event structure plus transformation operators, and uses Suno as a high-capacity performance/timbre generator whose outputs can be re-ingested into the structural system through stem-based MIDI extraction.
