# D01.02 Experiment Logging and Journaling Protocol

Document Status: Draft v0.1  
Date: 2026-07-30  
Parent: D01.00 Sectional Symbolic Recovery Master Proposal  
Applies to: D01.01 Melodyne + Suno Stem Feasibility Pilot

## 1. Purpose
This protocol defines how to log execution, observations, and decisions during the experiment so results are reproducible and auditable.

The design goal is to balance rigor with speed: enough detail to reproduce every result without slowing musical work.

## 2. Logging Layers
Use three layers of records.

1. Run Log: objective facts for each processing run.
2. Lab Journal: narrative observations, hypotheses, and anomalies.
3. Decision Log: explicit go/revise calls and why they were made.

## 3. Minimum Per-Run Record
Every run should capture these fields.

1. Run ID
2. Date/time
3. Operator
4. Section ID
5. Input file(s)
6. Tool and version
7. Command/settings
8. Output file(s)
9. Immediate result (pass/fail/warning)
10. Short note on what changed next

## 4. Run ID Standard
Use deterministic run IDs.

Pattern:

Sxx.xx-Rnn-YYYYMMDD

Examples:

1. S01.03-R01-20260815
2. S01.03-R02-20260816

## 5. Journal Cadence
Write journal entries at fixed checkpoints.

1. Pre-run intent: what you are testing and expected outcome.
2. Post-run observation: what happened and whether it matched expectation.
3. End-of-session synthesis: what was learned and what to do next.

Each entry should be short and factual first, interpretive second.

## 6. Decision Hygiene
When a change in approach occurs, capture a decision entry immediately.

Minimum fields:

1. Decision ID
2. Trigger evidence
3. Options considered
4. Chosen action
5. Risk of decision
6. Retest condition

## 7. Evidence Attachment Policy
For any non-trivial claim, attach at least one artifact reference.

Acceptable references:

1. output MIDI file
2. output audio bounce
3. screenshot of Melodyne analysis
4. stem reconstruction note
5. timing comparison snippet

## 8. Severity Tags
Tag issues consistently.

1. Critical: blocks completion or corrupts results.
2. Major: materially affects alignment or usability.
3. Minor: correctable nuisance.
4. Note: informative observation without immediate impact.

## 9. Session Close Checklist
Before ending a session, confirm:

1. all runs recorded
2. output files named and locatable
3. open issues tagged with severity
4. next first action documented
5. pilot gate status updated if relevant

## 10. Deliverables at Pilot End
The pilot is log-complete when these are present.

1. complete run log table
2. complete lab journal entries by session
3. complete decision log
4. concise end summary with Go or Revise recommendation

## 11. Journal Placement Rule (All Experiments)
Experiment-specific journal files should primarily contain real session entries, not repeated instruction blocks.

Use this allocation:

1. D-series protocol documents define how journaling works.
2. Experiment journals (for example S01, S02) store run-to-run observations, interpretation, and decisions.
3. Run reports store deep analysis for one run.

## 13. Iteration Artifact Naming Convention
Name artifacts consistently across loop iterations so any session can be reconstructed.

Pattern: `S[n]-<type>`

| Artifact | Name |
|---|---|
| Curated Suno master audio | `S[n]-master` |
| Suno stems bundle | `S[n]-stems` |
| Raw extracted MIDI (pre-cleanup) | `S[n]-midi-raw` |
| Cleaned/arbitrated MIDI | `S[n]-midi-clean` |
| Performance-mapped MIDI | `S[n]-midi-mapped` |
| Next symbolic generation source | `G[n+1]` |
| Updated transformation ruleset (if revised) | `F[n+1]` |

All artifact references in run log rows and journal entries should use this pattern.
