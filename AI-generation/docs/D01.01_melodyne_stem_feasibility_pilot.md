# D01.01 Melodyne + Suno Stem Feasibility Pilot

Document Status: Draft v0.1  
Date: 2026-07-30  
Role in Program: Step 1 pilot inside the larger sectional audio-to-MIDI recovery research stream

## 1. Purpose
This document defines a narrow first experiment to test whether Melodyne can recover compositionally useful MIDI from a representative generated passage, and whether Suno stem exports improve that recovery.

The pilot is intentionally limited. It is designed to answer feasibility questions before running the full multi-condition protocol.

## 2. Position in the Larger Research Program
This pilot operationalizes one bounded question inside the broader iterative Digital Performer-Suno-recovery workflow.

If this pilot succeeds, its methods and thresholds become the baseline setup for the larger comparative study. If it fails, the full protocol is revised before additional experiments are started.

## 3. Primary Questions
This pilot asks a small set of high-value questions.

1. Can Melodyne extract usable melody and bass MIDI from a representative Suno-generated section?
2. Does stem-based transcription outperform full-mix transcription for this section?
3. Are Suno stems sufficiently faithful to the selected mix to support reliable transcription work?
4. Is cleanup effort low enough to justify continuing this workflow at scale?

## 4. Success Criteria (Pilot Gate)
This section defines go/no-go criteria for moving to the next research step.

Proceed to the larger study only if all criteria below are met:

1. At least one Melodyne output (full mix or stem) preserves recognizable melody or bass contour.
2. The extracted MIDI can be aligned to meaningful measures/beats in the existing DP grid with manageable correction.
3. Cleanup time is materially lower than full manual retranscription, or produces materially higher creative value.
4. Suno stem behavior is documented and usable, even if stem reconstruction is imperfect.

If fewer than three criteria are satisfied, pause and revise procedure, source selection, or tool settings before continuing.

## 5. Representative Passage Selection
This section defines what counts as a representative test section.

Choose one passage meeting all of the following:

1. Length: 16 target measures with 2-measure handles on both sides.
2. Content: identifiable melody, clear bass function, moderate harmonic density.
3. Form: at least one phrase boundary and one cadence.
4. Texture: avoid exceptionally dense tutti material for this first pilot.

Record section metadata before any processing starts.

## 6. Fixed Conditions for Pilot 1
This section locks key settings so results are interpretable.

1. One selected Suno version only.
2. Melodyne as primary transcription engine.
3. Comparison scope limited to:
- Full selected mix (DP-positioned render)
- Melody stem
- Bass stem
- Harmonic/accompaniment stem
4. No aggressive preprocessing beyond level matching and documented trimming policy.

## 7. Required Materials
This section lists the minimum materials needed to run the pilot.

1. Digital Performer session with source and transformed section.
2. Selected Suno audio result.
3. All available Suno stems for that selected result.
4. Melodyne project file(s).
5. Evaluation logs and timing notes.

## 8. Procedure
This section defines the run order for Pilot 1.

### 8.1 Prepare and Place
This stage ensures a stable temporal reference.

1. Select target section and handles.
2. Place selected Suno result into DP against the source structure.
3. Bounce a DP-positioned transcription render from a known origin.

### 8.2 Stem Intake and Reconstruction Check
This stage validates whether stems are trustworthy enough for transcription.

1. Export all available Suno stems.
2. Import stems at common origin (do not align by first transient).
3. Build summed-stem reconstruction and compare with selected mix.
4. Log residual differences and practical implications.

### 8.3 Melodyne Passes
This stage generates raw symbolic outputs before cleanup bias is introduced.

Use these Melodyne algorithm assignments per input type:

| Input | Algorithm |
|---|---|
| Full mix or DP-positioned render | Melodic or Universal |
| Vocals / melody stem | Melodic |
| Bass stem | Melodic |
| Harmonic / accompaniment stem | Universal or Polyphonic (use cautiously) |
| Drums (if retained) | Percussive |

Run order:

1. Transcribe full DP-positioned render.
2. Transcribe melody stem.
3. Transcribe bass stem.
4. Transcribe harmonic stem.
5. Export raw MIDI from each pass before correction.

Treat stem-derived MIDI as higher-confidence than mix-derived MIDI where events conflict. Suppress cross-track pitch duplicates after all passes are exported.

### 8.4 Alignment and Cleanup
This stage tests whether recovered MIDI becomes usable without full retranscription.

1. Import all raw MIDI at common origin.
2. Measure global offset and local drift.
3. Apply minimal correction workflow (global offset first, then local fixes).
4. Prioritize melody and bass cleanup.
5. Log edit burden by category and time.

### 8.5 Compositional Trial
This stage tests practical musical value.

1. Reorchestrate cleaned melody/bass material in DP.
2. Render a short proof-of-use passage.
3. Decide whether material supports meaningful continuation.

## 9. Evaluation Rubric
This section defines how outputs are scored.

Use 1-5 scales for each condition:

1. Melody preservation
2. Bass preservation
3. Measure/beat alignment
4. Harmonic usefulness
5. Edit burden efficiency
6. Compositional usefulness

Suggested timing bands for onset checks:

- Excellent: <=30 ms
- Usable: <=75 ms
- Correctable: <=150 ms
- Poor: >150 ms
